# 端侧软件与工程样机技术分析：操作系统、应用与硬件 BOM

> **摘要**：工程样机在 **Debian 系**（默认 **Raspberry Pi OS**，或板厂 **Debian / Ubuntu**）上验证业务；量产在定制 SoC 板上交付 **同源工具链** 下的 **裁剪 Debian / Ubuntu**（只读根 + overlay 或 A/B + **签名 OTA**）。端侧采用 **薄 UI、`edge-daemon` 管硬件、稳定 IPC、systemd 托管**；打印走 **`lp` / CUPS**（或厂商 SDK 封装进 daemon）。**工程样机硬件 BOM、Bring-up、样机成本与 A5/ZINK 幅面口径**见 **§10**；**机身基准图与换壳资产流程**见 **§11**；仓库入口与 ZINK 话术另见根目录 [`../README.md`](../README.md)；产品级 SoC 与量产 BOM 见 [`1. 项目计划书.md`](1. 项目计划书.md) **§5.1 / §6.2**。

**文档范围**：**§1～§9**（**Part A**）为 **量产端侧软件**：背景、原则、OS、架构、选型、外设集成、工程/运维与安全测试；**§10**（**Part B**）为 **工程样机硬件**（BOM、Bring-up、成本与前置验证）；**§11**（**Part C**）为 **成品渲染与换壳**（机身基准 PNG、示意 SVG、资产流程）；**§12**（**Part D**）为关联文档索引；**§13**（**Part E**）为 **Android 技术方案**（技术备案，与 Debian 主路径的对比与搬迁评估）。下文 **「文档地图」** 给出推荐阅读顺序。本文 **不替代** PRD 全文与项目计划书财务算例。

## 1 背景与问题空间

儿童 AI 打印一体机的端侧需同时满足：**触屏看图确认**、**语音与 PTT**、**ZINK 走纸**、**家长锁与内容策略**、**可远程升级**。若工程样机与量产采用 **不同发行族或不同打印模型**（例如样机 Linux、量产 Android），会出现 **驱动与业务逻辑双份维护、联调结论不可继承** 的高返工风险。

**已定稿结论**：量产操作系统采用 **Debian / Ubuntu 嵌入式裁剪**；与工程样机所用 **Pi OS / 板厂 Debian·Ubuntu** 同属 **Debian 包命名空间**，以便 **打印栈、SSH 排障、依赖构建** 从样机平滑延续到量产 rootfs。

## 2 设计原则与样机 / 量产对照

### 2.1 路线原则（一致、低门槛、可演进）

1. **技术路线一致**：工程样机与量产 **共用同一套软件架构**（Debian 系、UI / `edge-daemon` 分层、IPC、打印抽象），**禁止**「样机一套演示栈、量产换引擎或换打印模型」；允许的差别仅限于 **系统形态（只读根、包白名单）、OTA、产测与性能指标**。
2. **硬件与依赖就低不就高**：在 **满足 PRD 体验**（触屏确认、语音、走纸、续航、家长锁等）前提下，**SoC / 内存 / 存储** 与软件依赖 **尽量少**；避免仅为样机演示而引入 **量产不会继承** 的外设或封闭中间件。具体选型以 **§10.3** 工程样机主清单与项目计划书 **SoC 线** 为准。
3. **为功能升级留白**：样机阶段即落实 **daemon + IPC + 可 OTA 分区布局**；业务与功能开关 **数据驱动**（配置文件与 overlay，见 **§8**），避免逻辑写死在 UI 或一次性脚本中，使后续 **云端能力、打印策略、家长策略** 迭代 **无需换板或推倒栈**。

### 2.2 端上 / 云端职责边界

| 维度 | 端上 | 云端 |
|------|------|------|
| **交互与管控** | 触屏看图确认、家长锁、本地缓存、调用打印 / 音频 / 网络 | ASR、文生图、审核、家长策略 |
| **实现约束** | UI **不**直接操作 USB 打印机字节流；经 IPC 调用 `edge-daemon` | 经 **HTTPS / MQTT** 与 **cloud-connector** 对接 |
| **运行与升级** | 根文件系统 **只读 + overlay**（或 A/B）；**systemd** 托管；**OTA** 升级 | 协议与内容策略版本迭代 |

### 2.3 工程样机与量产的本质差别

| 维度 | 工程样机（Debian 系：Pi OS / 板厂 Debian·Ubuntu） | 量产 |
|------|----------------------------------|------|
| **硬件** | 树莓派等开发板 | 定制 PCB + 选型 SoC / 存储 / 屏模组 |
| **系统** | 官方镜像，开发期可 `apt` 装包 | **裁剪 Debian/Ubuntu** + **只读根** + **受控 OTA**；**禁止**依赖终端用户 `apt upgrade` |
| **应用** | 可 Python + venv、Chromium kiosk 等快速验证 | 强调 **冷启动时间、内存占用、看门狗、OTA、签名校验** |
| **维护** | 人工 SSH | **远程 OTA**、日志与版本矩阵 |

量产阶段将目标从「能跑」提升为 **产线可烧录、现场可回滚、家长端可预期**。

## 3 操作系统基线（已定稿）

在 SoC 厂 **Linux BSP** 上交付 **裁剪后的 Debian 或 Ubuntu**（Server / Minimal / 板厂预集成镜像再瘦身均可），通过 **preseed、debootstrap 或镜像流水线** 移除与 PRD 无关的包，保留 **systemd、网络、音频、显示、USB、CUPS/IPP、OTA agent** 等必要栈。量产形态为 **只读根 + overlay**（或 **A/B rootfs**），内核与 rootfs 升级走 **签名 OTA**。

**Android**：**不作为本项目量产主路径**。若供应商将来 **仅** 提供 Android 打印 SDK，须走 **变更控制 / 单独立项** 再评估。

### 3.1 曾评估但未采纳的基线（备忘）

| 方案 | 概要 | 未作为主路径的原因 |
|------|------|-------------------|
| **Buildroot / Yocto 极小 rootfs** | 镜像更小、攻击面更可控 | 包生态弱于 Debian；从 Pi 样机迁移与联调成本高；**仅当存储或启动指标极端吃紧时** 再单列评估 |
| **Android** | HAL + 应用以 Java/Kotlin 为主 | 与仓库 **Linux + CUPS + ZINK** 主线不一致；打印与常驻后台服务不确定性大 |

### 3.2 镜像与包清单（与工程样机对齐）

量产 rootfs **不另起炉灶换发行族**，在 **与样机相同的 Debian/Ubuntu 包命名空间** 内做减法与冻结：

1. **样机冻结输出**：在 Pi OS 或板厂镜像上记录 **`uname -r`、CUPS/打印相关包、音频栈、显示栈** 版本；导出 **`dpkg --get-selections`**（或 Ubuntu manifest 等价物）作为 **白名单初稿**。
2. **流水线构建**：使用 **debootstrap + 显式包列表**（或板厂 SDK + 再瘦身）在 CI 中 **可重复构建** rootfs，与样机行为做 diff；禁止依赖工程师本机「随手 apt」。
3. **收口策略**：量产镜像 **仅含白名单包**；开发期调试包在 **发布分支** 剔除；与 **§10.4**「版本冻结」及 **§7.1** 工程习惯一致。
4. **内核与驱动**：跟随 SoC 厂 **LTS / BSP**；将样机已验证的 **屏、USB、声卡** 组合写入 **硬件兼容性矩阵**，OTA 升级时同步回归。

## 4 端侧应用架构

将 **硬件敏感逻辑** 与 **UI** 分离，便于产测 mock、OTA 分包与替换 UI 技术栈。

```
┌─────────────────────────────────────────┐
│  UI 层（看图确认、家长锁、设置）          │
│  全屏 kiosk 或 Qt 主窗口                 │
└─────────────────┬───────────────────────┘
                  │ 本地 IPC（D-Bus / Unix socket / gRPC；择一，全仓库统一）
┌─────────────────▼───────────────────────┐
│  edge-daemon（常驻，C++/Rust/Go）         │
│  · 打印队列 · ZINK/CUPS 或厂商 SDK        │
│  · 音频采集/播放 · 唤醒/PTT GPIO          │
│  · 离线任务队列 · 磁盘缓存                │
└─────────────────┬───────────────────────┘
                  │ HTTPS / MQTT
┌─────────────────▼───────────────────────┐
│  cloud-connector                        │
│  （可与 daemon 同二进制或拆分）           │
└─────────────────────────────────────────┘
        并行：ota-agent（A/B 分区 + 签名验签）
```

**架构约束**：UI 进程崩溃 **不丢失** daemon 内打印队列；`edge-daemon` **无界面**、可独立升级（与 **§7.6** OTA 包拆分策略一致）。

## 5 关键技术选型

### 5.1 UI 框架（三选一，可阶段切换）

| 路线 | 适用场景 | Debian 裁剪镜像注意点 |
|------|----------|------------------------|
| **Qt 6（QML/C++）** | 一体机动画、多页导航；与 Wayland/X11 集成成熟 | `qt6-base` 等须纳入 **manifest**；可交叉编译或板载原生构建 |
| **嵌入式 Web（本地 HTTP + WebView）** | 与样机 **Web + kiosk** 延续最快 | 量产优先 **Qt WebEngine** 或 **WPE WebKit**（`wpe-webkit`），避免完整桌面 Chromium；静态资源放只读分区 |
| **LVGL + 自绘** | 极低内存、极简 UI | 与 DRM/KMS 或 fb 绑定深，Bring-up 成本通常高于 Qt/Web |

**不建议作为量产默认**：嵌入式 Linux 上 **完整桌面 Chromium + Electron** 作为唯一 UI（内存与 OTA 体积压力大）。若产品坚持 Web UI，采用 **裁剪浏览器壳 + 单页应用**（WebEngine 或 wpe-webkit）。

### 5.2 与 `edge-daemon` 的 IPC 契约

须在仓库内维护 **OpenAPI 或 protobuf**（带版本号），至少覆盖：

- **预览**：云端预览 URL 或本地缩略图路径。  
- **打印任务**：任务 ID、纸张规格（A5 PRD）、色彩/线稿模式、优先级、超时。  
- **错误码**：可映射到 UI 文案（卡纸、缺纸、网络、审核拒绝等）。  
- **家长锁**：只读查询 + 受控写（daemon 侧校验）。

UI **仅通过 IPC 调用 daemon**，不直接执行 `lp`，以便权限收敛与产测替换实现。

## 6 打印、音频与触屏（集成要点）

- **打印**：UI → IPC → `edge-daemon` → **`lp` / libcups / 厂商 SDK`**。A5 与 ZINK 介质边界见 **§10.2** 及根目录 [`../README.md`](../README.md)。
- **音频**：优先 **PipeWire**（与多数 Debian 系镜像一致）；由 daemon 或 `audio-helper` 通过 IPC 暴露 **录音 / 播放 / 设备切换**，避免多进程争用设备。
- **触屏**：校准文件进入镜像只读层或 overlay；分辨率与 DPI 与 **PRD 屏规格**（见 **§10.3** 主清单 **E7**）一致。

## 7 工程方法、部署与运维

### 7.1 开发环境与迭代节奏（工程样机阶段）

- **IDE**：VS Code / Cursor **Remote-SSH** 至板端（`ssh` 开启；镜像与 **§10.4** 工程样机 OS 表一致）。  
- **依赖**：允许 `apt install` 调试包；**至少每周**导出 `dpkg --get-selections` 或与量产共用的 **包列表 YAML**，标注「仅开发 / 可进量产」。  
- **显示栈**：Wayland（如 labwc/Weston）或 X11；与量产目标 **尽早对齐**，避免量产更换合成器导致 Qt/Web 行为漂移。

### 7.2 量产前镜像收口

- 应用与依赖改为：**CI 内 debootstrap + manifest 安装**，或可复现的 **`.deb` / 静态二进制** 拷入 rootfs。  
- 移除开发用 SSH 私钥、编译器、无关字体与文档包（参见 **§10.4**「与量产衔接」表）。  
- **内核、CUPS、声卡** 版本登记入 **硬件兼容性矩阵**（与 **§3.2** 一致）。

### 7.3 交叉编译（可选）

在 **Debian/Ubuntu x86_64** 上使用与目标 ABI 一致的 **toolchain + sysroot**（或 `sbuild` / `pbuilder` arm64）。**debug 包** 仅进内测通道；发布通道 **strip + 符号表分离**。

### 7.4 systemd 与服务编排

| 单元 | 建议 |
|------|------|
| `edge-daemon.service` | `After=network-online.target`，`Restart=always`，限频重启；环境变量使用 `EnvironmentFile=-/etc/fancy-print/device.env`。 |
| `fancy-print-ui.service` | `After=edge-daemon.service`；失败策略与看门狗（含可选硬件狗）与产品约定。 |
| `ota-agent.service` | 独立用户与 capability；仅写入 OTA 分区与状态文件。 |

**图形会话**：kiosk 场景可用 **自动登录 tty + startx** 或 **Wayland compositor 自启**；避免完整 GNOME/KDE。

### 7.5 样机到量产迁移检查项

前提：样机已按 **§10.4** 选用 **Debian 系 OS**，并完成打印 / 音频 / 触摸等「与量产衔接」验证。

1. **接口契约先行**：在样机板上将预览、打印任务 JSON、错误码固化为 **OpenAPI 或 protobuf**，量产 `edge-daemon` **实现同一契约**，减少 UI 改动面。  
2. **业务逻辑上移**：ASR、文生图、审核尽量在 **云端**；端上聚焦 **缓存、重试、脱敏日志**。  
3. **打印抽象稳定**：样机可用 `lp`；量产在 daemon 内维护 **`PrintJob`** 抽象，底层接 **CUPS 或厂商闭源库**，UI 不感知。  
4. **配置单一来源**：使用 **统一配置文件**（只读分区 + 可写 overlay）描述打印机型号、屏参数、功能开关；产线 **逐台写入序列号与校准数据**。

### 7.6 OTA、版本与回滚

| 项 | 建议 |
|----|------|
| **分区** | **A/B rootfs** 或 **双槽镜像**；升级失败 **自动回滚** 至上一版本。 |
| **签名** | 镜像与增量包 **私钥签名、设备验签**；禁止未签名包写入启动分区。 |
| **通道** | **灰度发布**（内测设备号段 → 全量）。 |
| **遥测** | 脱敏上报 **崩溃栈、打印失败码、OTA 结果**；合规与隐私条款前置。 |

量产 **禁止**依赖用户执行 `apt upgrade` 随机升级内核；内核与 rootfs 变更纳入 **自家 OTA** 与版本矩阵。

### 7.7 产线、老化与 CI

- **工厂镜像**：一键烧录 **eMMC/闪存**；分区布局为 **裁剪 Debian/Ubuntu**（只读根 + overlay 或 A/B）；首次开机 **自检**（屏、触摸、麦、喇叭、走纸、WiFi）。  
- **老化**：高温高湿与 **连续打印 N 次** 纳入产测脚本，与 **§10.6** Bring-up 末环对齐。  
- **CI**：在 **Debian/Ubuntu 容器或 debootstrap 环境** 构建 **rootfs manifest** 与 **edge-daemon/UI**；执行 **单元测试 + 模拟打印**；关键路径可配置 **夜间硬件台架**（SoC 板尽量与样机/量产一致）。

## 8 安全、配置与隐私

**安全（儿童场景底线）**

- **HTTPS** 固定证书链、**证书钉扎**（视威胁模型）；密钥 **不得明文** 打入镜像，采用 **每机注入** 或安全元件。  
- **内容安全**：与云端审核策略一致；端上 **家长锁 / 打印确认** 与 PRD 一致。  
- **依赖与 CVE**：rootfs **最小包集**；建立 **CVE 扫描与 LTS 内核** 更新节奏。

**配置与隐私**

- **全局配置**：`/etc/fancy-print/config.yaml`（只读）与 `/var/lib/fancy-print/`（可写 overlay）分离 **静态配置与运行态**。  
- **密钥与凭证**：不进 Git；产线注入 WiFi 凭证、设备证书等。  
- **日志**：结构化日志与崩溃转储路径受控；上传前 **脱敏**（避免儿童语音原文等持久明文存储，与法务及 PRD 对齐）。

## 9 测试与版本交付物

### 9.1 测试矩阵（APP 团队）

| 类型 | 内容 |
|------|------|
| **单元** | IPC 编解码、错误码映射、离线队列重试。 |
| **集成** | daemon + CUPS 假队列 / 真机打印模组；断网、弱网、云端 429/5xx。 |
| **E2E** | Bring-up「连续对话打印 N 次」脚本化（见 **§10.6**）。 |
| **OTA** | A/B 切换后 UI 与 daemon 版本匹配；回滚后配置完整可恢复。 |

### 9.2 发布交付物（建议纳入版本发布说明）

1. UI 与 `edge-daemon` **可执行文件**及 **systemd unit** 文件。  
2. **IPC 契约**（OpenAPI / proto）与 **错误码表**。  
3. **manifest 片段**（应用依赖包列表，及与量产 rootfs 的合并说明）。

## 10 工程样机硬件 BOM 与集成清单（ZINK 打印一体机）

**§10 描述对象**：**第一台可拿得出手的工程样机** — **打印一体机**、**便于移动**、**约手机尺寸触控屏**（孩子看图确认后再打 ZINK 纸）。  
样机阶段允许 **亚克力 / 3D 打印堆叠**、线材外露；以 **功能闭环 + 可复现问题** 为优先，外观工艺后置。

**整机外观与换壳纪律**：对外与手板讨论须遵守 **§11** 的 **唯一基准图与 A/B 分层**；样机 **E13** 堆叠须预留与基准图一致的 **屏区、出纸口、PTT** 关系，避免手板与渲染各画各的。

**操作系统口径（与量产一致）**：量产已定为 **Debian / Ubuntu 嵌入式裁剪**（见上文 **§3**）。工程样机 **只选 Debian 系**：**Raspberry Pi OS**（Debian 同源）或 **板厂官方 Debian / Ubuntu** 镜像，**避免**样机用与 Debian 包体系不一致的发行版，以免打印栈与依赖到量产推倒重来。
**重要**：很多消费级 ZINK 机仅 **蓝牙 + 厂商 App**。工程样机主控若走 **Linux 单板**，务必提前验证打印机是否支持 **USB 打印类 / IPP** 或厂商 **ARM SDK**；否则打印链路会卡在工程样机之外。

### 10.4 工程样机操作系统（装什么）

**原则**：与上文 **§3**、**§3.2** 对齐 — 仅 **Debian 系**；开发期可用 **apt** 装调试包，**收口前**对照量产 **manifest 白名单** 删包并再测打印 / 音频 / 触摸全链路。

| 主控（E1） | 推荐系统 | 说明 |
|------------|----------|------|
| **树莓派 5**（文档默认） | **Raspberry Pi OS（64-bit）Bookworm** | **首选 [Lite](https://www.raspberrypi.com/software/operating-systems/)**：无桌面、省内存，适合自跑 **Qt / Wayland / Chromium kiosk** 做「看图确认」UI。需要快速摸屏、浏览器、CUPS 时用 **Desktop 版**，确认后再收敛到 Lite。 |
| 树莓派 5 | **Ubuntu Server 24.04 LTS（官方 Pi 镜像）** | 与量产 **Ubuntu 裁剪** 最接近；**须自行验证** USB 打印 + CUPS 全链路。 |
| **RK3588 等国产 ARM 板** | **板厂随附 Debian / Ubuntu 镜像** | 勿随便换「通用」第三方镜像，避免 **HDMI/MIPI 屏、WiFi、声卡** 驱动踩坑；与 **E7 屏** 绑定同一 BSP。 |

**不建议工程样机首版**：纯 **Yocto/Buildroot 极小系统**（除非有专职 BSP）。**Android 不作为本项目主路径**，首版勿在样机上赌 Android 打印栈。

**打印与音频**：用发行版自带的 **CUPS**（或厂商指定 **IPP/USB** 栈）接 **E5**；拾音放音走 **PipeWire** 或 **ALSA**（按镜像默认即可）。触摸屏在 X11/Wayland 下校准后 **冻结配置**。

**版本冻结**：记录 **镜像文件名、`uname -r`、关键包版本**；演示与评审前关闭 **无人值守升级**，避免「昨晚还能打、今早内核更了不能打」。冻结物应能喂给量产 **rootfs manifest**（见上文 **§3.2**）。

应用开发方式（UI 选型、Remote-SSH、CUPS、systemd 等）见上文 **§5**、**§7**。

#### 与量产「Debian / Ubuntu 裁剪」的衔接（收口检查）

| 检查项 | 样机阶段 | 量产前须完成 |
|--------|----------|----------------|
| **发行版族** | 仅 Debian 系（上表） | 同族 **裁剪 rootfs**；无发行版切换 |
| **包管理** | 可用 `apt` 迭代 | 镜像内 **移除 apt** 或禁用在线源；仅 **OTA** 升级 |
| **打印栈** | `lp` / CUPS 与 E5 绑定验证 | `edge-daemon` 内同一抽象；**不更换**为 Android 打印模型 |
| **证据留存** | 版本冻结记录 | `dpkg --get-selections` 或等价 **manifest** 入仓，与 CI 构建一致 |

**软件侧（工程样机必备）**：在 **Debian 系**镜像上固定 **OS 版本**、**内核 / CUPS / 应用** 的 commit；预装 **远程日志**（或网线 SSH）；打印前 UI 走 **确认 / 重试** 与 **线稿 / 淡彩内容策略**（与根目录 [`../README.md`](../README.md) 开篇 ZINK 产品话术一致）。产出须能映射到量产 **manifest**（见上文 **§3.2**）。

### 10.5 工程样机成本（物料 vs 量产）

工程样机成本通常按 **「散件零售价 + 试错备料」** 核算，**不等于**量产整机出厂价。量产方向性 BOM 见 [`1. 项目计划书.md`](1. 项目计划书.md) **§6.2**（当前文档内口径约 **物料 ¥398 / 含分摊与组装出厂约 ¥431**，随屏、机芯、电芯报价会变）。

#### 与量产的差异（为何样机会更贵）

#### 样机几千块，那整机零售价该定多少？

**结论先说**：工程样机 **¥3,000～¥5,000 一台的散件钱**，是 **研发 / 打样预算**，**不能**当成「整机就该卖这个价」，也**不要**按样机单价摊给消费者。

零售标价应锚定 **量产整机出厂成本（COGS）** + 渠道与税 + 毛利目标，见 [`1. 项目计划书.md`](1. 项目计划书.md) **§6.2**。当前文档里量产物料加总约 **¥398**，含开模分摊与组装后 **整机出厂约 ¥431**（会随屏、机芯、电芯报价浮动）。

| 你关心的 | 说明 |
|----------|------|
| **样机 vs 量产** | 样机用开发板零售价；量产用定制板 + 批量议价，**单台物料通常可明显低于样机**。 |
| **粗略倒推「能覆盖硬件成本」的标价** | 仅作数量级：若出厂 **≈¥431**，要留 **约 35～45% 硬件毛利**（未计平台扣点、售后、内容补贴），**含税零售价常落在 ¥650～¥950 一带**（`431 ÷ (1-0.4) ≈ ¥718` 起算，再叠渠道系数会更高）。 |
| **与 PRD ¥399～599 的关系** | 若 **坚持**该价位带，须在量产阶段 **压低 BOM**（主控/屏/机芯重选型）、或 **硬件微利 + 耗材/会员补贴模型**、或 **上调零售价**；三者至少落实其一，否则财务模型不自洽。 |
| **众筹早鸟** | 可略低于日常零售换种子用户，但应设 **台数上限 + 成本红线**，避免「卖得越多亏得越多」。 |

**一句话**：样机贵是正常的；**卖价**看 **量产 ¥431 这档能不能压下去 / 标价敢不敢上 ¥700+**，须与 [`1. 项目计划书.md`](1. 项目计划书.md) **§6.1～§6.3（定价 / BOM / 损益）** 一起 **滚动重算**，不要混用两套口径。

|------|----------------------|---------------------------|
| **尺寸** | **约 5.9～6.8 英寸**，与 PRD「手机屏量级」一致 | **7 英寸**（LVDS 接口） |
| **分辨率** | **FHD+ 长屏**，保证 PPI | **1024×600**（样机阶段够用；明显低于 FHD 的 PPI 不影响功能验证） |
| **面板** | IPS 或高质量 OLED；**勿 TN** | **TN 或 IPS**（取决于选配模组，建议确认出货面板类型） |
| **亮度** | **≥450 cd/m²** 起 | 一般 250～350 cd/m²（室内够用，窗边需遮光） |
| **触控** | 全贴合；**确认 / 取消 / 再打** 大触控区 | **电阻或电容触控**（取决于 LVDS 模组配套触控方案；建议优先电容） |
| **表面** | 雾面 / AR / 可选类纸膜，控反光 | 与模组相关 |
| **接口** | HDMI / DSI（取决于主控） | **LVDS**（RK3568 原生支持，40pin FPC 直连） |

> **LVDS vs 量产 HDMI 路径**：RK3568 的 LVDS 接口最多支持 1920×1080@60fps，7寸 1024×600 处于其规格下限，驱动稳定。若量产改用 HDMI 触控屏，只需在 Android BSP 的 `rk3568.dtsi` 中 disable LVDS、enable HDMI 即可，**上层 Android App 无需任何改动**。

## 13 Android 技术方案（技术备案）

> **定位**：本章是 **Android 端侧软件技术备案**，不作为本项目量产主路径替代（主路径已定稿为 Debian/Ubuntu 裁剪，见 **§3**），但为以下场景提供可参考的技术方案与评估：① 供应商 **仅**提供 Android 打印 SDK；② 市场或投资方要求 Android 生态兼容性；③ 产品线扩展至 Android 平板 + 打印配件模式。本章 **不推翻** §3「Android 不作为本项目量产主路径」的定稿结论，仅作为 **技术储备与搬迁成本指引**。

### 13.1 系统架构对照（Android vs Debian 主线）

#### 13.1.1 Android 层次概览

```
┌────────────────────────────────────────────────────┐
│  应用层（System UI / Launcher / 打印 App）           │
├────────────────────────────────────────────────────┤
│  Android 框架（ActivityManager / PrintManager /     │
│  AudioFlinger / InputManager / PackageManager 等）   │
├────────────────────────────────────────────────────┤
│  Android 运行时（ART / HAL / HIDL / AIDL）          │
├────────────────────────────────────────────────────┤
│  内核层（Linux LTS + Android 特有 patch：                           │
│  Binder / ashmem / 电源管理 / wakelock /                           │
│  双焦面 / dm-verity）                                │
└────────────────────────────────────────────────────┘
```

**与 Debian 主线的层次映射**：

| 层级 | Debian 主线（§4） | Android |
|------|-------------------|---------|
| **UI** | Qt / LVGL / 裁剪 Web（kiosk） | Android System UI / 定制 Launcher（Kotlin/Java/Compose） |
| **硬件服务** | `edge-daemon`（C++/Rust/Go）+ systemd | Foreground Service + HAL + PrintManager / AudioFlinger |
| **IPC** | D-Bus / Unix socket / gRPC（自家契约） | Binder（Android 核心 IPC）+ HIDL / AIDL（HAL 接口） |
| **进程生命周期** | systemd 托管；崩溃后 Restart=always | AMS（ActivityManagerService）；后台进程可能被 LMK 杀死；需 Foreground Service 保活 |
| **文件系统** | 只读根 + overlay 或 A/B； ext4 | super 分区（dynamic partitions）：system / vendor / product / odm；A/B 槽位；ext4 / f2fs |
| **驱动模型** | Linux 内核模块 + Device Tree | HAL + HIDL / AIDL；Treble 架构分离 vendor 与 system |
| **包管理** | apt / dpkg；manifest 白名单 | APK（Android Package Kit）；PackageManager；Google Play / 侧载 |
| **升级** | 签名 OTA 包；A/B rootfs 或双槽 | A/B 分区（Seamless Update） + SElinux + dm-verity |

#### 13.1.2 Treble / Project Mainline 的影响

Android 8.0+ 的 **Project Treble** 将 vendor 实现与 Android 框架分离，使 SoC 厂提供 **VNDK（Vendor Native Development Kit）** 兼容的 HAL 实现。**Project Mainline**（Android 10+）通过 Google Play 系统更新（APEX / APK-in-APK）直接推送框架模块更新，绕过 SoC 厂与 OEM 的长时间适配。

**对本项目的影响**：

- Treble 降低了 Android 版本升级对底层 BSP 的依赖，对长生命周期产品（如打印一体机）尤为重要。
- Mainline 使核心安全补丁可与 OEM 大版本解耦，缓解 Android 嵌入式设备「出厂即停更」的风险。
- **但**：打印相关 HAL 与 USB/蓝牙协议栈仍依赖 vendor 实现，SoC 厂若不维护，项目仍会卡 BSP。

### 13.2 ZINK 打印方案（Android 端）

#### 13.2.1 Android 打印架构

```
┌───────────────────────────────────────────┐
│  App（UI + PrintManager API）              │
│  val job = PrintManager.createPrintJob()  │
└──────────────────┬────────────────────────┘
                   │ Binder
┌──────────────────▼────────────────────────┐
│  Print Service（Mopria / 厂商定制）         │
│  · 发现打印机（USB / IPP / 蓝牙）           │
│  · 与打印机协商 PDL（ZINK 私有或光栅化）    │
│  · 提供 PrintAttributes（纸张、色彩、边距） │
└──────────────────┬────────────────────────┘
                   │ USB / 蓝牙 / WiFi
┌──────────────────▼────────────────────────┐
│  ZINK 打印机（USB 打印类 / 蓝牙 SPP / IPP）│
└───────────────────────────────────────────┘
```

Android 的打印框架以 **PrintManager API** + **Print Service** 为双核心：

1. **PrintManager**：系统服务（`system_server` 内），管理打印任务的生命周期（创建、提交、取消）。
2. **Print Service**：独立 APK，由打印机厂商实现，通过 `android.printservice.PrintService` API 注册。系统内置 **Mopria Print Service**（多数 Android 设备预装），支持 IPP / USB / 蓝牙打印机发现与驱动。

#### 13.2.2 ZINK 打印的三条路径

| 路径 | 原理 | 适用 | 关键风险 |
|------|------|------|---------|
| **USB 打印类（Mopria）** | ZINK 打印机实现 USB Printer Class（ IEEE 1284）；Mopria 自动发现，发送光栅化位图 **无厂商 SDK** 依赖 | USB 连接的 ZINK 打印机；Mopria 已覆盖大多数 USB 打印机 | ZINK 部分冷门机芯可能 **未实现** USB Printer Class，而是私有协议（仅蓝牙），此时 Mopria 无法识别 |
| **蓝牙 + 厂商 SDK** | 打印机厂商提供 Android SDK（AAR），通过蓝牙 SPP / BLE 发送位图数据 | 口袋 ZINK 打印机（如 HPRT、Phomemo 等国产蓝牙机型） | SDK 质量参差；**后台打印受限**；蓝牙传输不稳定；市面常见机型多为 **手机 App 模式**，ARM Linux 端 SDK 不一定存在 |
| **IPP（TCP/IP）** | 打印机支持 IPP（RFC 3510），通过网络直接提交打印任务 | 企业级或支持网络的高端机芯 | 工程样机阶段 E5 选型通常为 USB 连接的低成本机芯，**极少原生支持 IPP**；需确认机芯固件能力 |

#### 13.2.3 Android 端打印抽象层设计

若转向 Android，原 `edge-daemon` 的打印抽象应映射为 **Android Print Service** 实现或 **封装层**：

| Debian `edge-daemon` 打印抽象 | Android 对应 |
|------------------------------|-------------|
| `PrintJob` 封装（任务 ID、A5 幅面、色彩模式、超时） | Android `PrintAttributes` + `PrintJobId`；自定义可扩展 `PrintDocumentAdapter` |
| `lp` / CUPS 后端调用 | Print Service 的 `onPrintJobQueued()` 回调；USB 走 `UsbManager.requestPermission()` |
| IPC 暴露给 UI | UI 通过 `PrintManager.createPrintJob()` / `PrintManager.print()` 触发；或通过自定义 AIDL 接口（若需 `edge-daemon` 式精细管控） |
| 产测 mock 模式 | 可注入 mock Print Service；或使用 `PrintManager` 的测试 API |

**注意**：Android 的打印框架以 **用户主动发起** 为设计前提（弹出打印确认对话框）。对于「云端下发 → 自动打印」的无人值守场景（本项目的核心用例），需要 **绕过或扩展** PrintManager 的标准流程：
- 方案 A：自定义 **AIDL 服务**替代 PrintManager，直接走 USB/蓝牙发送位图数据（类似 `edge-daemon` 的直出模式），绕过系统打印 UI。
- 方案 B：使用 `PrintDocumentAdapter` 静默打印，通过 `android:allowMultipleScreens` 等 API 尝试抑制系统交互 — 但 **厂商兼容性不可控**。
- **建议**：Android 端采用 **方案 A** 作为主实现，以最大化对无人值守打印的控制权。

#### 13.2.4 ZINK 驱动现状（2025-2026）

- 大多数消费级 ZINK 打印机 **仅有移动端 SDK（iOS/Android AAR）或蓝牙私有协议**，**不提供** Linux CUPS 驱动。这是本项目 Debian 主路径的已知风险（§10 已有说明）。
- 若最终选型的 ZINK 机芯 **仅支持 Android SDK**，则 Android 路线反而成为 **唯一可行**的端侧方案 — 届时不再是与 Debian 的偏好选择，而是强制转换。
- **结论**：样机 E5 选型时，须 **同时评估** USB Printer Class 兼容性（Debian 路线）和 Android SDK 可用性（Android 备案路线），将驱动风险作为选型否决项。

### 13.3 音频、显示与触屏

#### 13.3.1 音频

| 维度 | Debian 主线（PipeWire / ALSA） | Android |
|------|-------------------------------|---------|
| **录音** | ALSA `arecord` 或 PipeWire 的 `pw-record`；daemon 可独占设备 | `AudioRecord` API；**多应用混音**由 AudioFlinger 自动管理；音频焦点（AudioFocus）防抢麦 |
| **播放** | PipeWire/ALSA `aplay`；需处理 **多进程争用**（由 daemon 仲裁） | `AudioTrack` / `MediaPlayer` / `ExoPlayer`；AudioFlinger 硬件混音；无需应用层仲裁 |
| **唤醒词 / PTT** | daemon 管理 GPIO 与 ALSA 设备切换 | Android 语音交互需 `MediaRecorder` 或 `AudioRecord` + 按键事件；PTT 通过 `KeyEvent` 或 `AccessibilityService` |
| **蓝牙音频** | 需 PipeWire 蓝牙模块（`pipewire-pulse` + `ofono` 或 BlueZ） | Android 原生 A2DP / HFP；**蓝牙耳机/音箱即插即用** — 对儿童产品场景（演示时蓝牙音箱）有明显优势 |
| **延迟** | 可 tuning 到 **极低**（ALSA 直出，无混音） | 非实时 OS；`AAudio` 在 Android 8.1+ 提供低延迟通路，但仍 **不如 ALSA 直出可控** |

#### 13.3.2 显示与触屏

| 维度 | Debian 主线 | Android |
|------|-------------|---------|
| **合成器** | Wayland（labwc/Weston）或 X11 | SurfaceFlinger + Hardware Composer（HWC）；对 GPU 利用率更高效 |
| **UI 框架** | Qt / LVGL / WPE WebKit（单进程强隔离） | Android View System / Jetpack Compose；**多窗口 / 通知 / 系统栏** 默认存在，需 kiosk 模式锁定制 |
| **触屏** | 校准文件（X11/Wayland） | InputManager 自动校准；多点触控原生支持 |
| **旋转管理** | 无统一旋转管理；需 udev 规则或 Wayland 旋转 | WMS（WindowManagerService）原生支持旋转；orientation lock API |
| **kiosk / 锁定制** | 自建（全屏窗口 + GPIO 锁 + 白名单进程） | Android **Lock Task Mode**（原 Kiosk Mode）：`startLockTask()` / Device Policy Controller（DPC） |
| **多屏扩展** | 可扩展（Wayland 多输出）但需配置 | Android 原生 **不支持多屏分离显示**（仅扩展屏镜像）；需 Android 10+ `Presentation` API |

**触屏适配要点**：Android 的 InputManager 对电容触控屏的原生支持好于 Debian（Debian 对非标触控模组常需手动校准与校准工具）。若工程样机 **E7 屏**选型为 HDMI+USB 触控，Android 端的 **即插即用概率更高**。

### 13.4 后台常驻服务（对标 `edge-daemon`）

#### 13.4.1 Android 后台限制（演进与现状）

这是 Android 作为 **打印一体机常驻 OS** 的最大挑战：

| Android 版本 | 限制 | 对本项目的影响 |
|-------------|------|---------------|
| **8.0 (API 26)** | 后台 Service 受限；`startService()` 在后台运行几秒后被系统停止；引入 `JobScheduler` | `edge-daemon` 式常驻进程必须改为 **Foreground Service** + 持续通知 |
| **9.0 (API 28)** | 后台 App 无法访问麦克风 / 摄像头 | PTT 录音需要在 **前台时** 捕获，或使用 Foreground Service + MediaRecorder |
| **10 (API 29)** | 后台 Activity 启动限制 | 下发打印任务时不可直接 `startActivity()`；需通过 Notification 或 JobScheduler 间接唤醒 |
| **12 (API 31)** | 前台 Service 启动限制（`foregroundServiceType`）；麦克风/摄像头指示器 | 打印服务须声明 `android:foregroundServiceType="dataSync"` 或 `"connectedDevice"` |
| **13+ (API 33+) | 通知权限运行时申请；更严格的 `SCHEDULE_EXACT_ALARM` | 打印超时 / 定时任务需适配 Android 13+ 的闹钟权限模型 |
| **厂商定制** | 华为、小米、OPPO、vivo 各自 **后台清理白名单** | 国产 ROM 会杀死非白名单的后台服务；需 **预置为系统级应用** 或走厂商通道 |

#### 13.4.2 Android 端 "edge-daemon" 服务架构

```
┌───────────────────────────────────────────────┐
│  App Process（主 UI 进程）                      │
│  · 看图确认 · 设置 · 家长锁入口               │
└──────────────────┬────────────────────────────┘
                   │ Binder / AIDL
┌──────────────────▼────────────────────────────┐
│  EdgeDaemonService（Foreground Service）        │
│  · PrintServiceBridge（USB / 蓝牙打印）        │
│  · AudioController（PTT / TTS）               │
│  · CloudConnector（HTTPS / MQTT）             │
│  · OfflineQueue + 磁盘缓存                    │
│  · JobScheduler 离线重试 / 定时维护            │
│  通知栏常驻：「正在管理打印任务」               │
└───────────────────────────────────────────────┘
        并行：OTA Service（使用 RecoverySystem API）
```

**关键设计要点**：

1. **Foreground Service 保活**：`EdgeDaemonService` 继承 `Service`，在 `onStartCommand()` 返回 `START_STICKY`，并传入 **持续通知**（`startForeground(NOTIFY_ID, notification)`）。通知文案面向儿童/家长：「奇想印印正在工作」。

2. **AIDL 接口**：定义 `.aidl` 文件暴露打印任务提交、状态查询、音频控制接口，UI 进程通过 `bindService()` 绑定调用。与 Debian 方案（D-Bus / gRPC / Unix socket）的 API 语义保持一致。

3. **JobScheduler 离线队列**：云端下发打印任务时如果网络不可用，将任务持久化到 SQLite/Room；注册 `NetworkType.CONNECTED` 的 `JobScheduler` 任务，网络恢复后自动重试。

4. **厂商 ROM 兼容**：
   - 在 `AndroidManifest.xml` 中声明 `android:persistent="true"`（仅系统应用有效）。
   - 若设备有 root 或系统签名，将 APK 预置为 `priv-app` 并加入厂商后台白名单。
   - 备选：使用 **AccessibilityService**（辅助功能）保活（有被滥用风险，非首选）。

#### 13.4.3 与 Debian `edge-daemon` 的能力映射

| 能力 | Debian `edge-daemon` | Android `EdgeDaemonService` | 差异等级 |
|------|---------------------|-----------------------------|---------|
| 硬件独占（打印 / 音频） | daemon 独占设备，无争抢 | 与其他 App 共享；需处理音频焦点、USB 权限弹窗 | ⚠️ **中** |
| 崩溃恢复 | systemd `Restart=always`，不受限 | Foreground Service 由 AMS 管理；崩溃后可自动拉起，但厂商 ROM 可能干预 | ⚠️ **中** |
| 启动自启 | systemd `WantedBy=multi-user.target` | `BOOT_COMPLETED` 广播 + Foreground Service；厂商可能会延迟或阻止自启 | ⚠️ **高** |
| 离线打印队列 | 本地磁盘缓存 + daemon 定时重试 | Room + JobScheduler；**JobScheduler 不可做高频轮询**（最小间隔 15 分钟） | ⚠️ **高** |
| 后台音频采集 | ALSA 直入，不受前台约束 | 后台录音受限；须在 PTT 按键时启动 Foreground Service + AudioRecord | ⚠️ **高** |
| 看门狗 / 健康监控 | systemd watchdog + 可选硬件狗 | `HealthMonitor` 定期上报到云端；无硬件看门狗标准机制；可走 `AlarmManager` 定时心跳 | ⚠️ **中** |
| OTA | A/B rootfs + 签名校验 | RecoverySystem API + A/B 分区（需 bootloader 支持） | — **见 13.5** |

### 13.5 OTA 与安全

#### 13.5.1 OTA 方案

| 维度 | Debian 主线 | Android |
|------|-------------|---------|
| **分区方案** | A/B rootfs 或双槽镜像；systemd 管理引导切换 | **A/B 分区（Seamless Update）**：slot A / slot B 交替；update_engine 在后台写入非活跃槽 |
| **触发方式** | ota-agent 下载签名包 → 标记启动槽 → 重启 | `RecoverySystem.installPackage()` 或 `UpdateEngine`（非 A/B 设备走 recovery）；支持后台下载更新 |
| **回滚** | 重启失败自动切回旧槽 | 新槽启动失败 → 自动回退；可通过 `update_engine` 状态确认 |
| **签名** | 镜像与增量包私钥签名、设备验签 | APK 签名（v1/v2/v3/v4）+ OTA 包签名（`otacerts`）；`dm-verity` 校验 system/vendor 完整性 |
| **增量包** | 可行（bsdiff / xdelta） | 原生支持增量 OTA（`/system` 分区差异） |
| **GP / 非 GP 设备** | 自家 OTA channel | 无 Google Play 服务的设备（国内版）：须自建 OTA 服务（下载 APK 全量包或增量包），走 `PackageInstaller` 安装 |
| **AOSP 构建** | — | 需要完整 AOSP 构建环境 + device tree + vendor blob；**构建门槛高于 Debian 的 debootstrap** |

**Android 无 Google 服务时的 OTA 流程（国内典型场景）**：

```
云端 OTA 服务器 → APK（全量更新）下载 → EdgeDaemonService 校验签名
  → PackageInstaller.installPackage() 静默安装（需 INSTALL_PACKAGES 权限）
  → 重启后新版本生效
```

**关键限制**：Android 的 `PackageInstaller` API 只能更新 APK，**不能**更新底层系统映像（kernel / vendor / HAL）。若要更新底层，仍需走 `RecoverySystem` + A/B OTA，这要求 OTA 系统包与设备 **使用相同签名密钥**，且构建基础设施与 AOSP 版本绑定。

#### 13.5.2 安全模型

| 维度 | Debian 主线 | Android |
|------|-------------|---------|
| **内核安全** | Linux 内核 + 可选 SELinux | 强制 SELinux（enforcing）；Linux 内核 LTS + Android 专用补丁 |
| **分区校验** | 可选（dm-verity） | **强制 dm-verity**（system / vendor 只读分区）；OTA 后自动重建 hash tree |
| **应用隔离** | 普通 Linux 用户 + 可选 AppArmor | **每个 App 独立 UID** + SELinux context；不同 App 默认不可互访数据 |
| **密钥存储** | TPM / 安全元件 / 文件系统加密 | **Android Keystore**（硬件背书的密钥库）；TEE（Trusted Execution Environment）；StrongBox（独立安全芯片） |
| **儿童防沉迷** | 无原生机制；自建家长锁 | **Android 家长控制**（`UserManager.createProfileForUser()` + `DevicePolicyManager`）；Google Family Link / 国内厂商儿童模式 |
| **CVE 响应** | LTS 内核 + debian-security 更新 | Android Security Bulletin（每月） + 厂商补丁 + Mainline 模块更新 |

**儿童场景的 Android 特有优势**：

- Android 提供 **Device Policy Controller（DPC） / Lock Task Mode**，可将设备锁定为单一应用（kiosk），儿童无法退出到桌面目由安装 App。
- **多用户模式**：将儿童使用限制在受控 profile 内，家长 profile 有完全控制权。
- **使用时长 / 应用限制**：`UsageStatsManager` + `DevicePolicyManager.setAppRestrictions()`。
- **但**：以上 API 中部分需要 **Device Owner** 权限（`DeviceAdminReceiver` 激活），在非 Google 服务设备上需设备厂商预置。

#### 13.6.2 工程样机硬件兼容性

工程样机主清单（**§10.3 E1～E15**）中，以下硬件在 Android 下的变化：

| 序号 | 配件 | Android 适配说明 |
|------|------|-----------------|

**工程样机 OS 装什么**：若测试 Android 路线，推荐以下配置（排除了 Android 移植质量不佳的树莓派）：

| 主控 | 推荐 Android 系统 | 说明 |
|------|------------------|------|
| **RK3568 K1 MINI**（本项目在用） | **官方 Android 14 BSP**（瑞芯微提供） | 四核 Cortex-A55 @2.0GHz，Mali-G52 GPU，满足 kiosk 渲染需求；原生支持 LVDS（7寸 1024×600）与 MIPI DSI；USB Host、蓝牙 5.0 完备；性价比高 |
| **RK3588 开发板**（Orange Pi 5 / FriendlyElec NanoPC-T6 等） | **官方 Android 12 / 13 BSP**（板厂提供） | **备选**：若 RK3568 算力不足（如需要端侧 AI 推理替代云端）时升级至此；GPU（Mali G610）/ NPU（6 TOPS）更强 |

**不建议**：在树莓派 5 上跑第三方 Android 移植用于工程样机（GPU 与视频编解码受限，与实际量产 Android SoC 驱动差异大）。

> **补充**：LVDS 屏的设备树（DTS）配置与 Android BSP 紧密耦合，首次点亮需板厂提供对应 kernel DTS 或自行适配 `/kernel/arch/arm64/boot/dts/rockchip/` 下的 `rk3568-k1-mini.dts`。

### 13.7 与 Debian 主路径的对比及决策矩阵

#### 13.7.1 全面对比

| 评估维度 | Debian 主线（**推荐**） | Android 技术备案 | 权重 |
|----------|----------------------|-----------------|------|
| **打印可控性** | CUPS / `lp` 完全控制；可静默打印；无人值守原生支持 | PrintManager 弹窗干扰；需绕过厂商 Print Service 定制 AIDL；无人值守需额外开发 | 🔴 **高** |
| **后台服务可靠性** | systemd 托管 + 硬件看门狗；无厂商干预 | Foreground Service + 厂商 ROM 白名单博弈；国产 ROM 杀死后台风险持续存在 | 🔴 **高** |
| **音频自由** | ALSA/PipeWire 直控设备；后台采集无限制 | 后台录音受限；需 Foreground Service + AudioFocus 管理 | 🔴 **高** |
| **OTA 自由度** | 自家 OTA 包 + 全量 rootfs；kernel 与应用统一升级 | APK 更新容易，系统映像更新依赖 AOSP 构建+RecoverySystem；无 Google 服务时底层更新复杂度高 | ⚠️ **中** |
| **触屏与显示** | 需手动校准；kiosk 自建 | InputManager 原生支持；Lock Task Mode 标准 kiosk；触屏兼容性好 | ✅ **Android 优势** |
| **电池管理** | 自建；依赖 `systemd-logind` + ACPI/GPIO  | BatteryManager API + 充电 HAL 成熟；国产手机级电源管理 | ✅ **Android 优势** |
| **蓝牙外设** | 需 PipeWire/BlueZ 调优 | Android 原生 A2DP/SPP/GATT；蓝牙打印即插即用 | ✅ **Android 优势** |
| **儿童安全** | 自建家长锁 + 审核策略 | DevicePolicyManager + Lock Task Mode + 多用户；标准化的儿童管控 API | ✅ **Android 优势** |
| **构建复杂度** | debootstrap + manifest + sbuild；相对轻量 | 完整 AOSP 构建需要大存储和高性能 CI（>300GB 磁盘，>32GB RAM）；仅 APK 可不用 AOSP | ⚠️ **中** |
| **开发者生态** | 嵌入式 Linux 开发者相对少 | Android 开发者基数大；Kotlin/Java 资源丰富 | ✅ **Android 优势** |
| **ZINK 驱动覆盖** | 依赖 USB Printer Class 或 CUPS 驱动；部分机芯无 Linux 驱动 | 多数消费 ZINK 机芯有 Android SDK（AAR）；蓝牙机芯 Android 兼容更好 | ✅ **Android 可能优势**（视选型） |

#### 13.7.2 决策建议

| 场景 | 建议 |
|------|------|
| **E5 打印选型确认有 Linux CUPS 驱动** | **坚持 Debian 主线**；Android 路径的高后台/打印改造成本不值 |
| **E5 打印选型仅支持 Android SDK** | **强制转向 Android 路线**；此时 Android 不再是「备案」而是唯一路径 |
| **产品要求蓝牙外设深度集成（蓝牙耳机 / 蓝牙游戏手柄等）** | **倾向 Android**；蓝牙生态深度显著优于 Debian |
| **儿童安全法规要求增强（如强制性家长控制认证）** | **可转向 Android**；利用 DPC / Lock Task Mode 降低合规成本 |
| **量产 SoC 厂商仅提供 Android BSP（如部分国产平板 SoC）** | **强制转向 Android**；SoC 选型阶段应将 BSP 策略纳入评估 |
| **产研团队以移动端/Java 为主，缺乏嵌入式 Linux 经验** | **倾向 Android**；团队学习曲线更短，但需补齐后台限制相关的专项知识 |

#### 13.7.3 若需转向 Android 的搬迁路径

1. **阶段一——E5 打印确认**：选型时明确机芯的 **Android SDK 兼容性** 与 **USB Printer Class 双重支持**。若仅 Android SDK，记录在 BOM 注释。
2. **阶段二——Android 样机搭建**：在 **RK3568 K1 MINI**上部署厂商 Android 14 BSP（瑞芯微官方），确认 7寸 LVDS 屏点亮、USB 打印通、音频录制回放可行。
3. **阶段三——`EdgeDaemonService` 原型**：实现 Android 版常驻后台（§13.4 架构），移植 IPC 契约（AIDL），验证无人值守打印流程。
4. **阶段四——OTA 与安全**：部署无 Google 服务的 OTA 通道（全量 APK），确认 Lock Task Mode kiosk 与家长锁。
5. **阶段五——量产物料切换**：与 SoC 厂商确认 Android BSP 基线、A/B 分区支持、SElinux 策略定制范围。

---

**§13 小结**：Android 作为端侧 OS 在 **触屏/蓝牙/儿童管控/开发者生态** 上有天然优势，但在 **后台服务可靠性/无人值守打印/音频独占** 三个核心维度上有显著约束。本项目的 Debian 主路径定稿（§3）在技术上是稳健的；Android 应作为 **受控的替代方案** 保留，并在 E5 打印选型时通过 **双路径兼容性验证** 锁定最终 OS 决策。

---

**结语**：量产端侧软件 = **裁剪 Debian/Ubuntu + 只读根或 A/B + 常驻 `edge-daemon` + Qt / LVGL / 裁剪 Web UI + 签名 OTA**；**Android 技术备案** 见 **§13**（当 E5 打印驱动 / 蓝牙需求 / 团队技术栈偏移时作为可评估路径）；**工程样机硬件、成本与 Bring-up** 见 **§10**；**整机渲染基准与换壳体系** 见 **§11**；与树莓派等工程样机的差异集中在 **系统形态、进程可靠性与升级机制**，**业务接口与打印抽象应自样机阶段对齐**，以控制从样机到量产的返工与风险。
